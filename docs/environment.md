# Environment variables

Source: `.env.example` at the repo root. Copy it to `.env` and fill in values.
**Never commit a real `.env` or real secrets.**

## Uploads / processing limits

| Variable | Default | Required | Notes |
|---|---|---|---|
| `MAX_UPLOAD_MB` | `2048` | No | Max upload size in MB |
| `MAX_VIDEO_DURATION_SECONDS` | `7200` | No | Max source duration (2 h) |
| `ALLOWED_VIDEO_EXTENSIONS` | `mp4,mov,mkv,webm` | No | Plus any FFmpeg-supported format |
| `PROCESSING_CONCURRENCY` | `1` | No | One job at a time on 8 GB RAM |
| `TEMP_RETENTION_HOURS` | `24` | No | Temp cleanup window |

> **PHP runtime limits (measured 2026-11-22):** Laravel allows clip
> uploads up to 2 GiB (`max:2097152` in the Muse clip endpoint), but
> stock PHP ships `upload_max_filesize = 2M` / `post_max_size = 8M`, so
> any real rendered clip (a 60 s 1080×1920 clip is 4–34 MB) is rejected
> by PHP with `UPLOAD_ERR_INI_SIZE` before Laravel ever sees it, and
> the API answers `422 {"errors":{"file":["The file failed to upload."]}}`.
> Set the values in the `php.ini` the server actually loads
> (`/etc/php/8.3/cli/php.ini` on this VM — verified: raising them only
> with `php -d … artisan serve` does **not** work, because `artisan
> serve` spawns a bare `php -S` child that never sees the parent's `-d`
> flags). The same applies to the user upload endpoint
> (`POST /api/v1/jobs` with `file`).

## Optional AI adapters (disabled by default)

| Variable | Default | Required | Notes |
|---|---|---|---|
| `OLLAMA_ENABLED` | `false` | No | Local LLM for semantic ranking |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Only if enabled | |
| `OLLAMA_MODEL` | *(empty)* | Only if enabled | Small local model recommended |
| `GEMINI_ENABLED` | `false` | No | Cloud adapter — needs the user's own key |
| `GEMINI_API_KEY` | *(empty)* | Only if enabled | **Never commit; never log** |

Core clipping works with both adapters disabled. Enabling Gemini may incur
costs on the user's own Google account — disclose before enabling.
